# Checkpoints and ADRs

After each answer, keep a short checkpoint:

```md
Decision: <resolved or deferred item>
Evidence: <facts and sources>
Assumptions: <unstated constraints>
Next: <one next action or question>
```

End with decided items, explicit deferrals, and unresolved blockers.

Write an ADR only when a decision is durable, affects multiple components or teams, and would be expensive to reverse. Record context, options considered, decision, consequences, and review trigger. Do not create ADRs for local implementation details or temporary choices.
