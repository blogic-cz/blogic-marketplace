# Checkpoints and ADRs

After each answer keep checkpoint:

```md
Decision: <resolved or deferred item>
Evidence: <facts and sources>
Assumptions: <unstated constraints>
Next: <one next action or question>
```

Confirm checkpoint when an answer changes scope, contract, risk, or canonical terminology. End with decided items, explicit deferrals, unresolved blockers, acceptance scenarios, and validation evidence needed.

Offer an ADR only when decision is hard to reverse, surprising without context, and result of real trade-off with durable architectural impact. An approved ADR records context, options considered, decision, consequences, and review trigger. Do not create ADR for local implementation detail, temporary choice, or interview note. Do not write an ADR/domain context until user approves final output plan.
